## Update — Circular gallery: mobile spin + shorter pin scroll

## Summary

**Spin:** `getPinZoneProgress` mixed Lenis **`scroll`** with viewport **`getBoundingClientRect`** deltas (incompatible), so progress stayed **~0** on many phones. Replaced with **pin vs `#main`** geometry (`- (pin.top - main.top) / (pinHeight - vh)`). Removed touch-only **`scroll`** throttling — use a **single `requestAnimationFrame` loop** so rotation updates during inertial scroll.

**Blank tail:** **`min-h-[260svh]`** on **`#carousel-pin-scroll`** created a very long dead zone on mobile; scaled to **`155svh` → `185svh` → `220svh` → `260svh`** by breakpoint.

## Update — Initial / route load: start at top of `#main`

## Summary

Scroll lives on **`#main`** (native **`overflow-y-auto`** or Lenis). On navigation the layout only called **`lenis.scrollTo(0)`**, which **no-ops when Lenis is not used**, so **`main.scrollTop`** stayed where the previous route left it. **Immediate** `main.scrollTop = 0`, **`window.scrollTo(0,0)`**, and **`history.scrollRestoration = 'manual'`** on mount; same **`scrollTop`** reset in **`Home.jsx`** after the intro loader.

## Changes

- Updated `src/pages/Home.jsx` — after loader, reset **`main.scrollTop`** / **`window.scrollTo`** before **`ScrollTrigger.refresh`**.

## Update — Scroll-to-top: Lenis timing, layout paint, BFCache

## Summary

Hard refresh and client navigations could still open **mid-scroll** because **Lenis** owns scroll on desktop while **`#main.scrollTop`** often stays **0**, resets ran **before** Locomotive finished its **500ms** init, and **`ScrollTrigger.refresh`** / **`initScrollReveal`** could nudge position **after** the first reset.

## Changes

- Added **`forceScrollMainToTop()`** in **`src/lib/utils.js`** — Lenis **`scrollTo(0, { immediate: true })`** when present, plus **`#main.scrollTop`** and **`window.scrollTo(0,0)`**.
- Updated **`src/app/layout.jsx`** — **`useLayoutEffect`** on **`pathname`**; **`pageshow`** listener; **`useEffect`** uses **`forceScrollMainToTop`**, double **`requestAnimationFrame`**, **850ms** follow-up after route transition; **`forceScrollMainToTop`** again **after** **`initScrollReveal`** (with rAF).
- Updated **`src/lib/locomotive.js`** — zero scroll **before** Lenis init, **after** first **`ScrollTrigger.refresh`**, on native-scroll path after proxy refresh; **“already initialized”** short path still calls **`forceScrollMainToTop`**.
- Updated **`src/pages/Home.jsx`** — post-loader block uses **`forceScrollMainToTop`** + post-**`initScrollReveal`** rAF passes.

## Notes

- If issues persist, next place to inspect is **Lenis `scroll` API** version mismatch or **pinned** ScrollTriggers on specific routes.
